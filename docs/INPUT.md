# 要件ヒアリングシート

このファイルに作りたいものの情報を記載してください。
記載後、`/project:requirements` を実行すると要件定義が作成されます。

---

## 1. 何を作りたいか？

自分が作ったプロダクトを一箇所にまとめて管理・公開できる**プロダクトハブサイト**。

プロダクトごとに以下のページを持つ：

- **LP（ランディングページ）** — 機能紹介、スクリーンショット、ダウンロードリンクなど
- **ヘルプ／ドキュメント** — 使い方ガイド、FAQ
- **リリースノート** — バージョンごとの変更点
- **法的ページ** — プライバシーポリシー・利用規約（App Store 申請などに必要）

新しいプロダクトが増えるたびに一から作るのではなく、**このサイトにプロダクトを追加するだけ**で完結させる。

---

## 2. なぜ作りたいか？

プロダクトを新しく作るたびに：

- プロダクトサイト・ヘルプサイトを別々に用意するのが大変
- デプロイ・ホスティング設定を毎回行う必要がある
- 複数サイトに分散して管理が煩雑になる

これらを解消するため、**1つのサイトで全プロダクトのページ・ドキュメントをまとめて管理**したい。

---

## 3. 誰が使うか？

各プロダクトのエンドユーザー（一般ユーザー）。

- 主に日本語ユーザー
- 英語ユーザーにも対応したい（日本語メイン、英語サブ）

---

## 4. 必須機能は何か？

- **トップページ（プロダクト一覧）** — 全プロダクトをまとめて紹介するハブページ
- **プロダクト LP** — プロダクトごとの紹介ページ（機能・スクリーンショット・ダウンロード）
- **ヘルプ／ドキュメント** — ステップバイステップのガイド、FAQ
- **リリースノート** — バージョン更新履歴
- **法的ページ** — プライバシーポリシー・利用規約（プロダクトごとに用意）
- **多言語対応（i18n）** — 日本語メイン、英語対応
- **統一リッチデザイン** — 全ページ共通の洗練されたデザイン（質素にしない）。ドキュメントページもカスタム CSS で整える
- **Markdown/MDX ベースのコンテンツ管理** — コンテンツはMarkdownで書けるが、見た目はリッチに（MDX でカスタムコンポーネント埋め込み）

## 6. その他（任意）

### 技術スタック（既存）

- **フレームワーク**: Astro v5 + Starlight v0.37
- **ホスティング**: GitHub Pages
- **CI/CD**: GitHub Actions
- **パッケージ管理**: pnpm

### 重要な設計方針

- **新プロダクト追加のコストを最小化** — 決まったフォルダ構成に従えば自動的にサイトに反映される構造が理想
- **デザインの統一感** — Starlight をカスタマイズして、LP もドキュメントページも同じブランドデザインに統一
- **machina.gg ブランドの強調は不要** — サイト自体のブランドより、各プロダクトを前面に出す
