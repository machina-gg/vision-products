# プロダクトハブサイト

> **SSOT**: このファイルは機能要件・制約の単一の情報源です

---

## 1. 概要

個人開発者が複数のプロダクトを持っている場合に、1 つのサイトで LP・ヘルプ・リリースノート・法的ページをまとめて管理・公開できるプロダクトハブサイト。新しいプロダクトを追加するたびに別サイトを作る手間をなくし、コンテンツを Markdown/MDX で書くだけで統一されたリッチなデザインで公開できる。

---

## 2. 背景・課題

プロダクトを新しく作るたびに：

- プロダクトサイト・ヘルプサイトを別々に用意するのが大変
- デプロイ・ホスティング設定を毎回行う必要がある
- 複数サイトに分散して管理が煩雑になる
- App Store 申請に必要な法的ページ（プライバシーポリシー・利用規約）を毎回作成・ホスティングしなければならない

既存の競合は「1 プロダクト = 1 サイト」または「チーム向けドキュメント管理」を前提として設計されており、個人開発者が複数プロダクトを一元管理するためのハブとして設計されたツールは存在しない。

---

## 3. ターゲットユーザー

- **主対象**: 複数のプロダクト（アプリ・ツールなど）を持つ個人開発者・インディーデベロッパー
- **エンドユーザー**: 各プロダクトのユーザー（ヘルプを参照する一般ユーザー）
- **言語**: 日本語メイン、英語サブ（i18n 対応）

---

## 4. 機能一覧

### MVP（必須）

#### ハブ機能
- **トップページ（プロダクト一覧）**: 全プロダクトをカード形式で一覧表示するハブページ

#### プロダクトごとのページ
- **LP（ランディングページ）**: ヒーローセクション・機能紹介・スクリーンショット・ダウンロード/ストアリンクを持つ紹介ページ
- **ヘルプ/ドキュメント**: ステップバイステップのガイド・FAQ をサイドバー付きで表示
- **リリースノート**: バージョンごとの変更点を時系列で表示
- **法的ページ**: プライバシーポリシー・利用規約（App Store / Play Store 申請に対応した URL を提供）
- **コンテンツ記事一覧**: そのプロダクトにタグ付けされた記事を絞り込んで一覧表示。URL は `/{product}/articles/`

#### サイト全体のコンテンツ記事
- **記事一覧ページ**: 全記事をまとめて閲覧できる。URL は `/articles/`
- **個別記事ページ**: SEO・教育目的の読み物記事（例: 「集中力を邪魔する要因Top3」）。URL は `/articles/{slug}`
- **プロダクトタグ**: 1記事に複数プロダクトをタグ付け可能。複数プロダクトに関連する記事は1本で管理し、各プロダクトの記事一覧にも表示される

#### サイト共通
- **統一デザイン**: 全ページ共通のリッチなデザイン（LP もドキュメントも同一ブランド）
- **多言語対応（i18n）**: 日本語メイン・英語サブのルーティングとコンテンツ切り替え。MVP から両言語に対応（VisionFocus は英語コンテンツが既存のため）
- **レスポンシブ対応**: モバイル・タブレット・デスクトップ対応

### 将来対応

- **検索機能**: ドキュメント横断の全文検索（Pagefind / Algolia DocSearch）
- **ブログ/アップデート**: プロダクトに紐付かない全体的な更新情報
- **OSS テンプレート化**: 同様のニーズを持つ個人開発者が fork して使えるテンプレートとして公開
- **アナリティクス連携**: Google Analytics / Plausible 等の統合

※ 実装状況は GitHub Issues で管理（PRD では機能定義のみ）

## 5. 非機能要件

| 項目 | 要件 |
|------|------|
| パフォーマンス | Lighthouse スコア 90+ (全カテゴリ) |
| ホスティング | GitHub Pages（無料） |
| デプロイ | main ブランチへの push で自動デプロイ（GitHub Actions） |
| 対応ブラウザ | Chrome / Safari / Firefox / Edge 最新版 |
| レスポンシブ | モバイル・タブレット・デスクトップ対応 |
| アクセシビリティ | WCAG 2.1 AA 準拠（Starlight のデフォルト機能を活用） |
| SEO | メタタグ・OGP・sitemap.xml 対応 |
| 言語 | 日本語（デフォルト）+ 英語 |

## 6. 制約・前提条件

### 技術的制約
- **フレームワーク**: Astro v5 + Starlight v0.37（既存）
- **ホスティング**: GitHub Pages（静的サイトのみ、サーバーサイド処理なし）
- **パッケージ管理**: pnpm
- **コンテンツ管理**: Markdown/MDX ファイルでの管理（CMS なし）
- **ビルド**: GitHub Actions で自動ビルド・デプロイ

### ビジネス上の制約
- 個人運用のため、継続的な運用コストはゼロを維持する
- コンテンツ追加・更新は開発者本人が Markdown/MDX で行う

### 設計方針
- **新プロダクト追加コストの最小化**: 決まったフォルダ構成に従えばサイトに自動反映される構造
- **ベンダーロックインなし**: すべてのコンテンツは Markdown/MDX で管理し、ツール乗り換えが容易な状態を維持
- **デザインの統一**: Starlight をカスタマイズして LP もドキュメントも同じブランドデザインに統一
